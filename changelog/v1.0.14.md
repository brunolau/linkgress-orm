# v1.0.14

## `isExternallyManaged()`: tables owned outside the model

A context often reads tables it does not own, such as a data warehouse's export or another service's
table. Until now the only way to map one was as an ordinary entity. Every difference between the
mapping and the owner's DDL then became an automatic migration, and `migrate()` tried to "repair" the
owner's table. Under a role that does not own the table, the whole migration failed with
`must be owner of table`.

```typescript
model.entity(SkiRun, entity => {
  entity.toTable('skied_kilometers');
  entity.toSchema('dwh');
  entity.isExternallyManaged();
  // …
});
```

- **An existing table** gets no planned operations. `analyze()` returns no column, index,
  extended-statistics, CHECK or foreign-key operation for it, and `ensureCreated()` adds none to it.
- **A missing table** is created from the model as before, with its indexes, CHECK constraints and
  foreign keys, so fresh, local and test databases keep working. After that it is left alone.

The flag reaches `TableSchema.externallyManaged`, which is only set on the tables that use it. Every
other table's schema keeps exactly the shape it had before.

Guide: [Migrations → Tables Owned Elsewhere](../docs/guides/migrations.md#tables-owned-elsewhere-isexternallymanaged).
Tests: `tests/schema/externally-managed.test.ts`. Two of its cases fail without the change to
`analyze()`/`ensureCreated()`, and a control case shows the same drift is planned without the flag.

### Upgrade notes

- No behaviour changes for entities that do not call `isExternallyManaged()`.
