# v1.0.38

`MutationBatch.addInsertBulkWithChildren` threw `insertWithChildren: rows resolve to zero insertable columns` when none
of its parents had a child, although its documentation says childless parents are allowed:

```typescript
const batch = new MutationBatch();
batch.addInsertBulkWithChildren(db.customFields, {
  rows: [{ name: 'Free text' }],
  children: { table: db.customFieldOptions, foreignKey: 'customFieldId', rows: [] },
}, 'fields');
await batch.executeBatch();
// 1.0.37: Error: insertWithChildren: rows resolve to zero insertable columns
```

gopass-eshop hit it cloning a product whose only custom field has no options (a free-text field): the clone's copy leg
had one parent and no child, and the save answered 500.

## Fixed: no child rows, no child CTE

The leg compiles its child INSERT from the columns of the child rows; with no rows it has none, and the compile threw.
When `children.rows` is empty the leg now stops after the parent and ordinal CTEs: it is a plain parent insert,
`getAffectedCount` still reports the parents and `parentReturning` still reads them back in input order. A misspelled
`foreignKey` still throws, rows or not. A leg with at least one child row emits the same three CTEs as before.

The standalone `insertWithChildren` and `insertBulkWithChildren` are unchanged: they require child rows (a parent that
needs none is an `insert()`), as documented.

## Tests

`tests/queries/mutation-batch-ibwc-leg.test.ts`:

- two parents and no child rows ride one statement, the parents read back in input order and the child table empty (on
  1.0.37 it throws);
- a childless leg without `parentReturning`, the shape gopass-eshop uses, rides next to another leg in the same statement
  (on 1.0.37 it throws);
- a misspelled foreign key still throws when there are no child rows.
