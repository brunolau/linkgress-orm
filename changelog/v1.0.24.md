# v1.0.24

## Fix: `lateralJoin()` is part of the select builder's type

v1.0.23 added `lateralJoin()` to `IEntityQueryable`, `DbEntityTable` and the collection query, and the runtime
`SelectQueryBuilder` already carries it. The typed `EntitySelectQueryBuilder` — what `where()`, `select()` and
`orderBy()` return — did not declare it. Two things broke:

- `db.<table>.select(…).lateralJoin(…)` worked at runtime but did not compile.
- A builder passed where `IEntityQueryable<any>` is expected stopped type-checking. Up to v1.0.22 the select
  builder matched that interface structurally; with the new member missing, the assignment fails with
  `TS2741: Property 'lateralJoin' is missing in type 'EntitySelectQueryBuilder<…>'`:

```typescript
const listAll = (query: IEntityQueryable<any>) => query.toList();

await listAll(db.users.where(u => eq(u.isActive, true)).select(u => ({ id: u.id, username: u.username })));
// v1.0.23: TS2741 — compiles again in v1.0.24
```

`EntitySelectQueryBuilder` now declares
`lateralJoin(navigation: (entity: EntityQuery<TEntity>) => unknown): EntitySelectQueryBuilder<TEntity, TSelection>`.
The navigation is typed over the ROOT entity, not the selection: the runtime resolves it against the root table,
whatever the projection is. Type-only change; the generated SQL is unchanged.
