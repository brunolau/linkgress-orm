# v0.4.46 (feat: add/sub/mul/div SQL arithmetic combinators)

The library exported `coalesce` but no arithmetic combinators, so any `a + b`
in a query had to drop out of the typed API into a raw `` sql`` `` template —
re-deriving column typing, mapper handling and parameter binding by hand each
time. Measured on a real consuming codebase, 21 of 53 `` sql`` `` fragments
existed purely to do arithmetic, most commonly the conditional-increment idiom
repeated verbatim across services:

```typescript
// before
.update(c => ({ usedCount: sql`${c.usedCount} + ${n}` }))

// after
.update(c => ({ usedCount: add(c.usedCount, n) }))
```

The four combinators (exported from the package root alongside `coalesce`):

```typescript
add(a, b, ...rest)   // (a + b + ...)   variadic
mul(a, b, ...rest)   // (a * b * ...)   variadic
sub(left, right)     // (left - right)  binary
div(left, right)     // (left / right)  binary
```

- **Operands take the same `FieldLike<T> | T` union as `coalesce`** — columns,
  `SqlFragment`s and plain literals all work, and all four return
  `SqlFragment<number>`, usable anywhere a fragment is (select projections,
  `where`, `update` values, nested inside other combinators). Literal operands
  bind as `$n` parameters, never inlined into the SQL text.
- **Mapper handling mirrors `coalesce` exactly**: the first operand-provided
  custom-type mapper wins, and its `toDriver` is applied to plain literal
  operands so they bind in driver representation against typed columns.
- **Output is always parenthesised.** `COALESCE(...)` is self-delimiting;
  infix arithmetic is not — emitting `(a + b)` means nesting composes without
  precedence surprises: `add(a, mul(b, c))` renders `("a" + ("b" * $1))`.
- **NULL semantics are unchanged**: `NULL + 1` is `NULL` in SQL and stays so —
  these compose with `coalesce` rather than replacing it:
  `add(total, coalesce(bonus, 0))`.
- **`sub` / `div` are deliberately binary, not variadic** — both operators are
  left-associative, so a variadic form reads ambiguously (`sub(a, b, c)`:
  `a - b - c` or `a - (b - c)`?). Longer chains nest explicitly:
  `sub(sub(a, b), c)`. PostgreSQL integer division still truncates — cast an
  operand for a fractional result.

**Known limitation (pre-existing, shared with `coalesce` / `jsonbMerge`):**
the comparison helpers bind a `SqlFragment` passed as the VALUE argument as a
bound parameter instead of inlining its SQL, so `lt(p.stock, add(p.reserved, 10))`
does not render the arithmetic — build such comparisons as a raw `` sql`` ``
fragment for now.

## Testing

  output per operator, variadic forms, column / literal / `SqlFragment`

  arithmetic in `select` and `where`, increment and decrement in `update`,
