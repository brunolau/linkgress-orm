# v1.0.45

## Fixed: a value compared with a mapped column of a grouped query's row binds through the column's `toDriver`

A grouped query evaluates the projection before `groupBy()` over a row of its own. That row's columns carried no
mapper, so a value compared with a mapped column there was bound as the application value, not as `toDriver` makes it.
That holds for a comparison inside an aggregate's argument, inside a grouping key, in a `having()` over a key, and in
the condition of a join to the grouped query. PostgreSQL refused the statement:

```typescript
// posts.customDate: integer column, custom mapper Date <-> seconds since 2025-01-01
db.posts
  .select(p => ({ userId: p.userId, later: caseWhen(gt(p.customDate, cutoff), 1).else(0) }))
  .groupBy(r => ({ userId: r.userId }))
  .select(g => ({ userId: g.key.userId, later: g.sum(r => r.later) }))
  .toList();
// SUM(CASE WHEN "posts"."custom_date" > $1 THEN CAST($2 AS integer) ELSE CAST($3 AS integer) END)
// 1.0.44: $1 = the Date -> invalid input syntax for type integer (22P02), in memory too
// 1.0.45: $1 = -30326400 (toDriver(cutoff)), as in a plain select() or where()
```

`GroupedSelectQueryBuilder.createMockRow()` now gives each column of the grouped table its mapper (`__mapper`), as the root
mock row of a plain query does. A navigation's and a manually joined table's columns already carried theirs. A join
to the grouped query (`grouped.innerJoin(subquery, (l, r) => …)`) hands its left side a ref per projected column, and
that ref now keeps the column's mapper too (`createMockForSelection`). Reads do not change: the grouped select already
looked each column's mapper up in its table's schema.

Not changed: comparing a `g.min()` / `g.max()` of a mapped column with a value in `having()` still binds the value
unconverted. The aggregate's ref carries no mapper, as before.

## Tests

`tests/queries/toDriver-mapper.test.ts` ("GroupBy with Date Fields"): a `caseWhen(gt(p.customDate, cutoff), 1)` in
the projection before `groupBy()`, summed by `g.sum()` and used as the grouping key, and `gt(l.customDate, cutoff)` in
the condition of a join to the grouped query. Each binds `toDriver(cutoff)` and returns the right rows. On 1.0.44 all
three fail on both engines with `invalid input syntax for type integer`.
