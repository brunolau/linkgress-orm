# v1.0.45

`coalesce()` over columns that carry no mapper read its result through the generic conversion, the one an untyped
`sql` template reads through, so a numeric-looking string became a number. Over text columns that is a name, not a
number: a digits-only value came back as a JS number, and a long one lost its last digits past 2^53:

```typescript
// invoice_record.document_number / b2b_invoice.document_number are varchar
const row = await db.eInvoiceSubmissions
  .where(s => eq(s.id, id))
  .select(s => ({ documentNumber: coalesce(s.invoiceRecord.documentNumber, s.b2bInvoice.documentNumber) }))
  .firstOrDefault();
// 1.0.44: { documentNumber: 90003526000000030 }  (stored: '90003526000000034')
// 1.0.45: { documentNumber: '90003526000000034' }
```

gopass-eshop hit it twice on one admin page: the e-invoice list showed the wrong number for every invoice numbered with
digits only, and its "Download XML" answered 500 because `documentNumber.replace(…)` is not a function of a number.

## Fixed: `coalesce()` over text reads as a text

When no operand carries a mapper, at least one operand declares a type and every one that does declares `text` or
`varchar` (`character varying`, with or without a length), the result reads as a `text` column, exactly as
`.withReadType('text')` reads, with no change to the SQL. A numeric-looking value stays the string the driver
delivered.

An operand's type is a column's declared type (a navigation's column too), a read-typed fragment's read type, or the
type a scalar subquery of one unmapped column reads as (`coalesce(db.t.where(…).select(t => t.code).asSubquery('scalar'), '')`).

The read type travels wherever a projection is read back (nested objects, `first()`, QueryBatch parts, UNION legs,
CTE and table-subquery columns), as `withReadType()` does. A list bound against such a CTE column with `eqAny()` is
cast `::text[]`.

## Unchanged: every other `coalesce()`

The fix is deliberately this narrow. Any other `coalesce()` builds the same untyped fragment it built in 1.0.44, so it
reads and compares exactly as before:

- over numbers (`integer`, `bigint`, `numeric`, …), dates, `uuid`, `json` / `jsonb`, `char(n)`, `citext`;
- over a mix of types (`coalesce(smallintColumn, integerColumn)`, a text column with a number);
- with no typed operand at all (plain values, an `sql` template);
- with a mapped operand, which still wins and reads the result through its mapper.

Typing those by their first operand was tried and dropped, because the declared type of one operand is not the type
PostgreSQL gives the result, and a read type reaches further than the read:

- a grouped select hands a `numeric` / `bigint` back as the driver's exact string; typed, the coalesce read a JS
  number there (`'99.99'` → `99.99`, an int8 past 2^53 rounded);
- `agg.max(coalesce(numericColumn, 0))` read `3` where it read `'3.00'`;
- a CTE column of `coalesce(smallintColumn, integerColumn)` carried `smallint`, so `eqAny(cte.k, [1, 40000])` bound
  `$1::smallint[]` and failed with `value "40000" is out of range for type smallint`.

`char(n)` and `citext` stay untyped because they compare differently from `text` (padding, case), and a CTE column
typed `text` would compare a bound list as text. Type such a coalesce yourself: `.withReadType('text')`, a `literal()`
fallback or `castAsString()`.

`declaredSqlType()` / `operandSqlType()` moved from `sql-functions.ts` to `conditions.ts` (internal) so `coalesce()`
reads an operand's type the way the aggregate helpers do.

## Tests

- `tests/queries/projection-reads.test.ts`: `coalesce()` over two text columns, over a text column with a plain
  fallback, nested and through a navigation reads `'90003526000000034'` / `'01234'` as strings (on 1.0.44:
  `90003526000000030` and `1234`); in a grouped select over a navigation's `decimal` column it still returns the
  driver's string.
- `tests/queries/fragment-read-type.test.ts`: which operand types make the result a text and which leave it untyped;
  against the database, `text` with `varchar`, a scalar subquery operand and a QueryBatch part read `'007'`; a CTE
  column of a text coalesce matches a text list; a CTE column of `coalesce(smallint, integer)` matches a list beyond
  smallint; `agg.max()` over a numeric coalesce still reads `'3.00'`.
