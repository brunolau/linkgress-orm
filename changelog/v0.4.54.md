# Fix: width-exact flag masks — `flagHas*` emit `& $1::smallint` / `::bigint`

The flag helpers (`flagHas`, `flagHasAll`, `flagHasAny`, `flagHasNone`) now
resolve the COLUMN's integer width from the schema and cast the mask to it
explicitly:

```sql
-- smallint column                      -- integer column        -- bigint column
("t"."mode" & $1::smallint) = 0         ("t"."flags" & $1) = 0   ("t"."big" & $1::bigint) = 0
```

## Is the cast needed semantically? No.

An untyped bind parameter was ALREADY inferred to the column's width by
describe (`int2 & $1` resolves the `int2 & int2` operator), so the column was
never converted at runtime and no behavior changes — for smallint/bigint
columns the folded expression tree is byte-identical to what the previous
uncast emission produced.

## What it fixes: the expression-tree lottery.

The SAME predicate produced DIFFERENT trees depending on how the statement
was (re)produced:

- runtime (bound param):     `(variant_mode & '1'::smallint)`  — int2 form
- inlined int4 literal:      `((variant_mode)::integer & 1)`   — the COLUMN
  gets promoted instead (logs replayed by hand, psql diagnostics, generated
  reports)

Expression statistics match trees exactly, so a statistic built against one
form is invisible to the other. In production this cost a 122M-row read 13×
(2,337ms vs 172ms): the plan-shape statistic was built from hand-inlined
EXPLAINs (int4 form) while the app's prepared statements produced the int2
form, re-enabling a mis-estimated cross join.

With the width carried in the SQL text itself, every reproduction — driver,
psql, a colleague pasting from the query log — folds to the SAME tree, and
one statistics form per column is provably sufficient.

## Mechanics

Schema-aware mock builders (entity roots, reference-navigation paths, update
mocks) now stamp `__sqlType` onto column FieldRefs; the flag helpers append
the matching cast. int4 columns stay uncast (bare parameter and bare literal
both land on int4 already). Column refs without type information (CTE
columns, post-select shapes) keep the historical uncast emission.

Covered by the `typed mask` block in `tests/queries/flag-operators.test.ts`
(emission per width incl. navigation paths + end-to-end filtering).
