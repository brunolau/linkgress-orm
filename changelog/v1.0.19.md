# v1.0.19

## Fix: a collection's `orderBy()` after `select()` reads the projection

A collection's `orderBy()` written after `select()` / `selectDistinct()` was handed the collection's item, not
the projection its selector is typed with. A key naming a projected field therefore read the item's column of
that name:

- a field the projection renames (`book.editions.select(e => ({ tag: e.label })).orderBy(e => e.tag)`) named no
  column, and the key was dropped from the ORDER BY without an error. With a `limit()` or `firstOrDefault()`,
  the collection returned an arbitrary row instead of the first one;
- a field named like another column of the item (`select(e => ({ label: e.category.name }))`, then
  `orderBy(e => e.label)`) ordered by that column, the edition's own label, instead;
- a field named like a navigation of the item (`{ category: e.category.name }`, then `e => e.category`) read
  the navigation's row, which `orderBy()` refuses as a key.

The projection of a flattened collection (`selectMany(e => e.loans.select(ln => ({ text: ln.note })))`) had
the same problem.

After a projection, `orderBy()` now reads it, as the selector's type says. A field reads as the value it
projects: a column, including a navigation's column, as that column, and an expression as that expression. A
name the projection does not select still reads the item's column or navigation, so ordering by a column the
projection leaves out still works. A projection of a single value (`e => e.label`) has no fields, and
`orderBy()` reads the item there, as before. Keys written before `select()` are unchanged.

Guide: [Querying → Ordering Collections](../docs/guides/querying.md#ordering-collections).
Tests: `tests/queries/collection-orderby.test.ts`, "collection ORDER BY after select(): the projection's
fields", under every collection strategy (lateral, cte, temptable). It covers a renamed column (also with
`limit()` and `firstOrDefault()`), a field named like another column, a field named like a navigation, a
projected SQL expression, a `selectDistinct()` projection and a flattened collection's projection; all of them
fail without the fix. One more case checks that a column the projection leaves out still orders, and "the ORDER
BY each strategy renders" checks the LATERAL form, `ORDER BY "lateral_0_editions"."label" DESC LIMIT 1`.

### Upgrade notes

- A collection that orders after `select()` by a field the projection renames now orders by the projected
  value. Before, the key was ignored, or ordered by the item's column of that name. To order by the item's
  column where the projection reuses its name for another value, order before `select()`:
  `orderBy(e => e.label).select(e => ({ label: e.category.name }))`.
- No change for keys written before `select()` or for projections of a single value.
