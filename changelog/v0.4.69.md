# v0.4.69

## Performance: per-schema column metadata (kills the `colBuilder.build()` storm)

Every query build called `colBuilder.build()` for **every column** of every touched schema —
in the main-table mock row, the reference mock descriptors, the collection mock item, the
ORDER BY db→property map, the temp-table primary-key probe, and — worst — **`mapDeleteReturningResults`
ran it per column PER RESULT ROW** on `returning: true` shapes. On a wide schema under load
this was a measurable slice of request CPU (`_createMockRow` alone ~2.6 % of process CPU in a
gopass-eshop purchase-path profile, with the shared `get`/`build()` machinery several points more).

Schemas are immutable after registration, so all of it is now served from one
`getSchemaColumnMeta(schema)` — a `WeakMap` keyed by schema identity holding
`{ mapper, type, name, primaryKey }` per column, computed once per schema object. Behaviour
is identical (the metadata comes from the same `build()` call, just cached); no switches, no
opt-in — the values are pure functions of the schema.

Full suite: 1,524 tests pass unchanged.
