# v0.4.71

## Feature: `eqAny` / `neAll` — list membership bound as ONE parameter, cast from the column type

`inArray` renders one placeholder per element, so its statement text changes with the list
length. [v0.4.70](v0.4.70.md) named the consequence for the new `preparedStatements` option:
*"Statements rendered with `IN ($1, $2, …)` lists are cached once per list length; that is
bounded for small lists and wasteful for large ones."* Until now the only way out was a raw
fragment — ``sql`${oi.productPriceId} = ANY(${ids}::int[])` `` — which hard-codes the element
type at the call site and silently rots when the column's type changes.

```typescript
db.orderItems.where(oi => eqAny(oi.productPriceId, boundPriceIds));
// "oi"."product_price_id" = ANY($1::integer[])

db.orderItems.where(oi => neAll(oi.productPriceId, excludedPriceIds));
// "oi"."product_price_id" <> ALL($1::integer[])
```

One parameter for a list of 3 or 3,000, and therefore one statement text — which is what makes
such a query reusable as a prepared statement.

### The cast is resolved from the column, not the call site

Both operators read the FieldRef's `__sqlType` — the same declared-type channel `flagHas`
already uses for width-exact mask casts — so the element type follows the schema:

| Declared column type | Emitted cast | |
|---|---|---|
| `integer`, `text`, `uuid`, `numeric`, `timestamptz`, … | `::integer[]`, `::text[]`, … | as declared |
| `serial` / `smallserial` / `bigserial` | `::integer[]` / `::smallint[]` / `::bigint[]` | pseudo-types have no array form (`serial[]` does not exist) |
| `char(n)` | `::bpchar[]` | `char[]` means `character(1)[]` — it truncates every element to its first character and then matches **nothing** |
| custom-mapped (`enumType`, `vector`, …) | `::order_status[]`, `::vector(3)[]` | `mapWith()` overwrites the declared type with the mapper's `dataType()` |
| `array`, or no type info (CTE columns, post-select shapes) | *(uncast)* | PostgreSQL infers the array type from the `ANY` context |

Custom mappers also apply per element: a `HourMinute` column's `toDriver` runs on every value
before the list is serialized, exactly as `inArray` does.

The list is bound as a PostgreSQL array LITERAL string (`{4,8,15}`), reusing the serializer
behind the `array()` custom type. That is the one encoding all three drivers accept — pg and
postgres.js serialize raw JS arrays themselves, but Bun's SQL client sends them as JSON
(protocol error 08P01). Both operators are verified against `PgClient`, `PostgresClient` and
`BunClient`.

### Semantics are identical to `inArray` / `notInArray`

Including the edges: an empty list gives `= ANY('{}')` (FALSE) and `<> ALL('{}')` (TRUE), the
same results as the `1=0` / `1=1` short-circuits — but without a second statement text. A NULL
column, or a NULL in the list, filters the row out under `neAll` just as it does under
`notInArray`. Navigation-property fields resolve their JOIN like any other condition.

### When NOT to use it

The trade-off is planning, not correctness. A literal `IN` list tells the planner exactly how
many values it will see; a parameter array falls back to a default selectivity estimate. Keep
`inArray` for short lists in queries you have hand-tuned around that exact estimate — the same
caveat v0.4.70 raised for wide analytical shapes under `preparedStatements`. Reach for `eqAny`
on hot lookups whose list length varies, and on lists long enough that the parameter count is
itself a cost.

Tests: `tests/queries/any-array-operators.test.ts` (20 cases). Twelve pin the emitted SQL — the
cast per declared type, the pseudo-type and `bpchar` normalizations, uncast fallbacks, per-element
mapper application, the single-parameter guarantee at 500 elements, literal escaping. Eight run
against PostgreSQL: row-for-row parity with `inArray` / `notInArray` including NULL and empty-list
handling, every declared column type accepted by the server, a custom-mapper column, a
navigation-property field, and one statement text across list lengths 1/3/200 where `inArray`
produces three. The suite passes under all three drivers.
