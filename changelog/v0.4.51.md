## Fixes: QueryBatch fidelity sweep — precision, binary, literals, mappers

A systematic fidelity sweep (`tests/queries/query-batch-fidelity.test.ts`: a
type-zoo table covering every declarable column type with hostile values, a
query-shape matrix, and a 12-branch kitchen-sink batch) surfaced and fixed
four transport bugs. Batched results are now proven value-AND-JS-type
identical to standalone execution across the full type and shape space.

### Fix: bigint / decimal / numeric beyond float53 precision

`to_json` emits arbitrary-precision JSON numerals, but `JSON.parse` collapses
them to floats — `9007199254740993` silently became `...992`, and a
19-significant-digit numeric lost its tail. Unrecoverable client-side, so the
envelope now casts declared bigint/decimal/numeric columns `::text`
server-side (a `to_jsonb(row) || jsonb_build_object(col, col::text)` override
carried via `FutureBatchMeta.textColumns`) — text IS the drivers' delivery
form for these types, at any precision, in flat and nested projections alike.

### Fix: bytea

Drivers deliver byte buffers; `row_to_json` emits the `\x…` hex text. The
reviver now decodes hex back to a `Buffer` (`Uint8Array` where Buffer is
unavailable).

### Fix: `$N` sequences inside SQL string literals

Cross-branch parameter renumbering was a bare regex over the branch SQL, so a
branch at a nonzero offset corrupted dollar-digit sequences INSIDE quoted
literals (`'price: $1'` → `'price: $8'`). Renumbering is now quote-aware:
single-quoted literals (with `''` escapes) and double-quoted identifiers pass
through verbatim.

### Fix: QueryBatch JSON revival must not outrun custom `fromDriver` mappers

A column with a DECLARED `timestamp`/`timestamptz`/`date` type AND a custom
mapper (`hasCustomMapper`) broke inside a batch when the application configures
its driver with parser passthrough (timestamps delivered as text): the reviver
converted the json string into a `Date` before the mapper ran, and a mapper
written against the driver's text output (`value.replace(' ', 'T')` →
Temporal, the shape a Temporal-based timestamp extension takes) crashed with
`value.replace is not a function`.

The custom mapper is the column's type authority. For mapper columns the
reviver now reconstructs the driver's TEXT-protocol form instead of a JS value:

- `timestamp`/`timestamptz`: json's ISO `T` separator → the driver's space
  (`2026-08-12T09:30:00` → `2026-08-12 09:30:00`)
- `date`: json `YYYY-MM-DD` already IS the driver text form — no revival
- `decimal`/`numeric`/`bigint`: unchanged — the string forms already match the
  driver text output

Columns WITHOUT a custom mapper keep the driver-equivalent JS revival
(`Date`, scale-formatted strings) exactly as in v0.4.50.

Regression coverage: `tests/queries/query-batch.test.ts` adds a
parser-passthrough postgres.js context with a
declared-timestamp + string-surgery mapper column (`posts.string_stamped_at`,
`debug/types/text-timestamp.ts`) proving batch === standalone.
