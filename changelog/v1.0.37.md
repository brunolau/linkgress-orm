# v1.0.37

Under TypeScript 7 (`tsc` 7, `bun check`), the subquery comparison helpers reported TS2345 on their column whenever the
subquery selected a one-column projection, which is the usual way to write one:

```typescript
db.users.where(u => inSubquery(u.id, db.posts.select(p => ({ id: p.userId })).asSubquery()));
// error TS2345: Argument of type 'DbColumn<number>' is not assignable to parameter of type 'FieldRef<any, { id: number; }>'.
```

All eight helpers did: `inSubquery`, `notInSubquery`, `eqSubquery`, `neSubquery`, `gtSubquery`, `gteSubquery`,
`ltSubquery` and `lteSubquery`. TypeScript 6 and earlier compiled the same calls, and nothing differed at runtime.
gopass-eshop had 87 such calls.

## Fixed: `T` comes from the column

A helper inferred its `T` from two places: the column and the subquery's rows. A one-column projection's rows are
`{ id: number }`, not `number`, and through the published declarations a `Subquery`'s `TResult` constrains nothing
(declaration emit drops the types of its private fields). TypeScript 6 and earlier settled on the column's type.
TypeScript 7 settles on the rows' type, then rejects the column.

Each helper now has two signatures:

- **First:** takes `T` from the column alone (`NotInferred<T>`, an indexed access on a deferred conditional that
  infers nothing). `NoInfer` would read the same from TypeScript 5.4 on; this form holds in every version a consumer
  compiles with.
- **Second:** the 1.0.36 signature, unchanged, so every call that compiled before still compiles. A subquery whose rows
  are wider than the column (`unknown[]`, `(number | null)[]`), which linkgress's own sources do check, widens `T` there
  as it did.

The change is in the declarations only. The emitted JavaScript is the same, except that three doc comments moved onto
the first signatures. A call that neither signature accepts now reports TS2769 ("No overload matches this call")
instead of TS2345.

## Tests

`tests/types/subquery-helper-inference.test.ts` compiles two projects, each with the installed TypeScript (5.9.3) and
with TypeScript 7 (`bun check`; skipped on a Bun without it):

- **A consumer of the emitted declarations:** 17 one-column calls through the eight helpers, and eight assertions that
  `T` is the column's type.
- **A file compiled against `src`:** a subquery wider than its column, through all eight helpers.

On 1.0.36 the consumer fails under TypeScript 7 with 17 × TS2345. With the first signatures alone, the `src` file fails
under both versions.

Checked outside the suite: a consumer of the emitted declarations compiles the same on TypeScript 5.0.4, 5.3.3, 5.4.5,
5.9.3 and 6.0.3 before and after, and on 7.0.2 it is clean only after. gopass-eshop's seven packages go from 87
(server) and 37 (frontend) TS2345 to none under TypeScript 7, and stay clean under 6.0.3.
