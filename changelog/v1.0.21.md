# v1.0.21

## Added: window ranking functions — `win.rowNumber()`, `win.rank()`, `win.denseRank()`

Window functions could only be written as raw `sql` templates (`sql<number>\`ROW_NUMBER() OVER (…)\``). The ranking
functions are now fragments of their own, built like the `agg` aggregates:

```typescript
db.members.select(m => ({
  id: m.id,
  rowInClub: win.rowNumber().over({ partitionBy: m.clubId, orderBy: [[m.points, 'DESC'], m.id] }),
}))
// row_number() OVER (PARTITION BY "members"."club_id" ORDER BY "members"."points" DESC, "members"."id" ASC)
```

- `win.rowNumber()`, `win.rank()` and `win.denseRank()` return a `WindowFragment<number>`; `.over({ partitionBy,
  orderBy })` returns a new one over that window (a window given before is replaced). Without `over()` the window
  is empty: `OVER ()`.
- `partitionBy` takes a column or an expression, or a list of them; `orderBy` takes the ORDER BY keys of the list
  aggregates — a key or `[key, 'ASC' | 'DESC']`, every key rendered with its direction. A plain JS value as a key
  is refused with a `TypeError` naming the function.
- A navigation used only in a key is joined; parameters number in textual order (the PARTITION BY keys, then the
  ORDER BY keys). The value reads as a JS number.
- Unlike an `AggregateFragment`, a window value keeps every input row: a select of window values is not a whole-set
  aggregate.
- It can be selected anywhere a projected expression can — an entity select, a CTE body, a table subquery, a
  collection navigation's select — and ordered by. A collection that projects one renders as LATERAL whatever the
  collection strategy, so it numbers each parent's items: the CTE and temp-table strategies aggregate the items of
  every parent in one pass, which would number them together.
- PostgreSQL computes window functions after WHERE, so a window value is filtered where a CTE that computes it is
  read: `db.selectFromCte(cte).where(r => eq(r.rowInClub, 1))`, also as the `inSubquery(…)` of an entity query. A
  `where()` on it in the query that computes it — or a join's `on` / filter over that projection — is refused with
  a `TypeError` naming the value: such a condition can only reach the alias, which that query has no column for,
  or which names a column of the table that it would filter instead.

The in-memory database already evaluated `row_number` / `rank` / `dense_rank` windows and `AT TIME ZONE`; nothing
changed there.

Exports: `win`, `WindowFragment`; types `WindowOptions`, `WindowFunctions`. Docs: `docs/guides/sql-expressions.md`
("Window functions (`win`)"), `docs/guides/querying.md` ("Window Functions").

Tests: `tests/queries/window-functions.test.ts` — rendering (the empty window, PARTITION BY / ORDER BY with
directions, parameter order, immutability, refused plain keys, the number read) and, on PostgreSQL and in memory:
numbering and ranking per partition with ties, a navigation used only in a partition key, a window computed in a
CTE body and filtered by the CTE's reader and through an IN subquery, the `where()` on it in its own query refused
(also under an alias a column of the table has, which it used to filter instead), a window in a collection
navigation's select numbered per parent under the lateral, CTE and temp-table strategies (the latter two numbered
the items of all parents together), and a partition by the local day of a UTC timestamp across a daylight-saving
switch.
