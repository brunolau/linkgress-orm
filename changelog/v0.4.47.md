## `mergeBulk` — PostgreSQL MERGE with per-query identity

New entity-level `mergeBulk(values, config)` (PostgreSQL 15+). Unlike `upsertBulk`/`ON CONFLICT`, which require a unique or exclusion constraint as the conflict arbiter, `MERGE` matches on the statement's own `ON` condition — the identity column(s) are declared explicitly at the call site and no index is consulted:

```typescript
await db.registryItems.mergeBulk(items, {
  on: 'crmId',                       // required — per-query identity column(s)
  matchWhere: 't."active" = TRUE',   // optional raw scope; target alias `t`, source `s`
  updateColumns: ['name', 'active'], // WHEN MATCHED arm; [] renders DO NOTHING
});
```

Renders:

```sql
MERGE INTO "registry_items" AS t
USING (VALUES ($1::boolean, $2::varchar, $3::varchar), (...)) AS s ("active", "name", "crm_id")
ON t."crm_id" = s."crm_id" AND (t."active" = TRUE)
WHEN MATCHED THEN UPDATE SET "name" = s."name", "active" = s."active"
WHEN NOT MATCHED THEN INSERT ("active", "name", "crm_id") VALUES (s."active", s."name", s."crm_id")
```

Details:

- first `VALUES` row is cast to the declared column types so source columns type correctly (serial pseudo-types cast to their integer base);
- `updateColumns` / `updateColumnFilter` / `chunkSize` / `referenceItem` / `SqlFragment` values behave as in `upsertBulk`;
- `.returning()` supported on PostgreSQL 17+ (columns target-qualified — both aliases are in scope in `MERGE … RETURNING`); navigation properties are not supported;
- Postgres contract caveats documented on the method: dedupe inputs by the `on` key(s) (a target row matched by two source rows raises `MERGE command cannot affect row a second time`), and MERGE has no `ON CONFLICT`-style speculative insertion — prefer `upsertBulk` for hot concurrent paths, `mergeBulk` for single-writer sync/batch flows.
