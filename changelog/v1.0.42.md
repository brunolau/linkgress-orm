# v1.0.42

`insertBulk` sent NULL for a cell a row lacked when another row of the same statement set that column, while a column
no row set was left out and took its DEFAULT. The same input meant two things, and on a `NOT NULL DEFAULT` column the
mixed statement failed:

```typescript
await db.registryItems.insertBulk([
  { crmId: 'a', name: 'set', active: false },
  { crmId: 'b', name: 'omitted' },               // registry_items.active is NOT NULL DEFAULT true
]);
// 1.0.41: null value in column "active" of relation "registry_items" violates not-null constraint (23502)
```

gopass-eshop hit it importing coupon codes: one `insertBulk` mixing pool rows (no `awardOrdinal`) with user-bound rows
(an `awardOrdinal`) on `discount_code.award_ordinal NOT NULL DEFAULT 1`.

## Fixed: a cell a row lacks is `DEFAULT`

A cell whose key is absent from the row, or `undefined`, now renders the `DEFAULT` keyword in that row's VALUES tuple and
binds no parameter, so each row gets what it would get inserted alone:

```sql
INSERT INTO "users" ("username", "email", "is_active") VALUES ($1, $2, $3), ($4, $5, DEFAULT)
-- params: [ "mia", "mia@test.com", false, "noah", "noah@test.com" ]
```

- An explicit `null` stays NULL. A column with no default gets NULL from `DEFAULT`, as before.
- Every statement `insertBulk` builds: with `onConflictDoNothing`, `returning`, `chunkSize`,
  `toStatement()`, and `MutationBatch.addInsertBulk` legs (they compile the same statement).
- With `overridingSystemValue` the identity column is in the column list: a row without an id now gets the generated
  one (before: NULL, which an identity column refuses).
- A mapped column's `toDriver` is no longer called for a cell a row lacks.
- The in-memory database already accepted `DEFAULT` in a multi-row `VALUES` list and applies the column default.

Unchanged, still NULL for such a cell: `upsertBulk` (its DO UPDATE reads the cell through `EXCLUDED`, so `DEFAULT`
would overwrite the stored value with the default), and the inserts that read their rows as a table — a `rowGuard`
insert, `insertWithChildren` / `insertBulkWithChildren`, `fromRows()` — where `VALUES` cannot hold `DEFAULT`.
